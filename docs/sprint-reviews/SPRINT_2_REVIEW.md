# Backend Changes

## API Endpoints

### `POST /executions/start`

Purpose:

Start a workflow execution.

Impact:

Supports deterministic workflow execution lifecycle.

---

### `GET /executions/{id}`

Purpose:

Retrieve execution details and timeline.

Impact:

Enables execution inspection and diagnostics.

---

### `POST /executions/{id}/replay`

Purpose:

Replay failed executions with corrected payloads.

Impact:

Supports recovery and comparison workflows.

# AI / Workflow Changes

## Deterministic Workflow Engine

This sprint intentionally avoided LLM orchestration.

Workflow logic is deterministic and rules-based.

### Replay Logic

Replay bypasses failures by injecting corrected payloads generated by the `CorrectionService`.

### Benefits

- predictable behavior
- easier debugging
- lower operational complexity
- MVP-first implementation
